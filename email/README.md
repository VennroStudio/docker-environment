# Email

Stalwart для почты, ClamAV для проверки писем и Bulwark для веб-почты. Каждый сервис работает в отдельном контейнере.

## Быстрый старт

Команды выполняются из папки `email`. Сначала создай `.env`:

```bash
make env
```

Отредактируй `.env` и проверь конфигурацию:

```bash
make config
```

Укажи тот же `PROJECT_NAME` и `NETWORK`, что у остальных модулей и Nginx Proxy Manager. В этом окружении это `docker-environment` и `proxy`.

**Не запускай модуль одновременно с Mailu:** оба используют порты `25`, `465`, `993` и `4190`. Сначала подготовь перенос почты и освободи порты, затем:

```bash
make init
```

Команда:
- скачает образы указанных версий,
- создаст внешнюю сеть `NETWORK`, если её ещё нет,
- создаст Docker volumes для данных,
- поднимет контейнеры Stalwart, ClamAV и Bulwark.

`make env` не перезаписывает существующий `.env`. Домены, TLS, DNS, антивирусная проверка и публичный прокси настраиваются отдельно. Данные Mailu автоматически не переносятся.

Из корня проекта модуль запускается командой `make email`, а `.env.prod` отправляется командой `make deploy-email`. Общие `make init` и `make deploy` используют `email` вместо прежнего `mail`. Корневой `make init` пропускает модуль, если `email/.env` ещё не создан.

## Настройка `.env`

Перед первым запуском отредактируй `.env`:

| Переменная | Описание |
|---|---|
| `PROJECT_NAME` | Общая группа контейнеров, `docker-environment` |
| `NETWORK` | Внешняя сеть NPM, `proxy` |
| `STALWART_CONFIG_VOLUME` | Имя volume конфигурации, `vennro-email_config` |
| `STALWART_DATA_VOLUME` | Имя volume почты, `vennro-email_data` |
| `CLAMAV_VOLUME` | Имя volume антивирусных баз, `vennro-email_clamav` |
| `MAIL_HOSTNAME` | Почтовое имя сервера, например `mail.example.com` |
| `STALWART_VERSION` | Версия образа Stalwart, сейчас `v1.0.0` |
| `ADMIN_PORT` | HTTPS-порт на `127.0.0.1` для доступа с сервера или через туннель, по умолчанию `19018` |
| `SETUP_PORT` | HTTP-порт настройки и админки через SSH на `127.0.0.1`, по умолчанию `19019` |
| `BULWARK_VERSION` | Версия веб-почты, `1.18.0`, совместимая со Stalwart 1.0 |
| `BULWARK_DATA_VOLUME` | Volume настроек и состояния Bulwark, `vennro-email_webmail` |
| `WEBMAIL_JMAP_URL` | Публичный URL Stalwart JMAP, например `https://mail.example.com`, без `/jmap` |
| `WEBMAIL_PORT` | Локальный порт Bulwark, по умолчанию `19020` |

Часовой пояс `Asia/Krasnoyarsk` задан в Compose. `.env` не хранится в Git. Если файл уже существует, добавь в него новые переменные из `.env.example`.

## Порты

| Порт хоста | Назначение |
|---|---|
| `25` | SMTP, приём писем от других серверов |
| `465` | SMTP TLS, отправка писем из приложений и клиентов |
| `993` | IMAP TLS, чтение почты |
| `4190` | ManageSieve, управление пользовательскими фильтрами |
| `127.0.0.1:${ADMIN_PORT}` → `443` | HTTPS Stalwart через локальный порт |
| `127.0.0.1:${SETUP_PORT}` → `8080` | Первоначальная настройка и админка через SSH |
| `127.0.0.1:${WEBMAIL_PORT}` → `3000` | Прямой доступ к Bulwark через SSH |

Порты ClamAV на хост не публикуются. Stalwart обращается к нему внутри отдельной сети `email`. Stalwart и Bulwark подключены к внешней сети `NETWORK` для доступа из NPM.

## Данные

Хранятся в именованных Docker volumes:

| Volume | Данные |
|---|---|
| `${STALWART_CONFIG_VOLUME}` | Конфигурация Stalwart, `/etc/stalwart` |
| `${STALWART_DATA_VOLUME}` | Данные Stalwart, `/var/lib/stalwart` |
| `${CLAMAV_VOLUME}` | Антивирусные базы, `/var/lib/clamav` |
| `${BULWARK_DATA_VOLUME}` | Настройки Bulwark и постоянный секрет сессий, `/app/data` |

Папки для данных на хосте вручную создавать не нужно. `make down` сохраняет volumes. Не используй `docker compose down -v`: эта команда удаляет volumes вместе с данными.

Имена volumes заданы явно и по умолчанию сохранены от прежнего проекта `vennro-email`: смена `PROJECT_NAME` не должна создавать пустое хранилище вместо существующей почты. Если модуль уже развёрнут, сначала останови старые контейнеры с прежним Compose-конфигом, сохранив volumes, и только затем запускай обновлённый модуль. Если использовались другие имена volumes, укажи именно их в `.env`.

У модулей общий Compose-проект. Предупреждение об orphan-контейнерах может относиться к соседним модулям: не используй `--remove-orphans` для его устранения.

## Первоначальная настройка

Посмотри пароль первоначальной настройки в логах Stalwart:

```bash
make logs SERVICE=stalwart
```

Или выполни на своём компьютере через SSH, чтобы показать блок с временными учётными данными. Замени `SSH_HOST` на имя подключения из `~/.ssh/config`:

```bash
ssh SSH_HOST 'docker logs stalwart-container 2>&1 | grep -A8 "temporary administrator account"'
```

Для первого входа используй логин `admin` и пароль из строки `password:`.

Не публикуй этот пароль. На своём компьютере открой туннель через тот же SSH-профиль:

```bash
ssh -N -L 20019:127.0.0.1:19019 SSH_HOST
```

Открой `http://127.0.0.1:20019` и пройди мастер настройки. Если меняешь `SETUP_PORT`, замени серверный порт `19019` в команде.

После завершения мастера сохрани логин и пароль постоянного администратора в менеджере паролей: пароль показывается только один раз и не записывается в логи. Затем **на сервере** перезапусти только Stalwart, чтобы выйти из режима первоначальной настройки:

```bash
docker restart stalwart-container
```

ClamAV перезапускать не нужно. Проверь запуск Stalwart:

```bash
docker logs --tail=100 stalwart-container
```

После перезапуска временная учётная запись больше не используется. Для постоянного входа по HTTP через SSH зарегистрируй OAuth-клиент по инструкции ниже. Без него вход через `http://127.0.0.1:20019/admin/login` может завершаться ошибкой `Unknown client id`.

Для общего `make tunnel` добавь в корневой `.env` нужные строки без `#` перед значением:

```dotenv
T_EMAIL_ADMIN=20018:127.0.0.1:19018
T_EMAIL_SETUP=20019:127.0.0.1:19019
T_EMAIL_WEBMAIL=20020:127.0.0.1:19020
```

Для входа по HTTP через SSH оставь `T_EMAIL_SETUP` включённым и сохрани публикацию `127.0.0.1:${SETUP_PORT}:8080` в Compose. Туннель только перенаправляет порт: он не настраивает TLS, OAuth и ограничения администратора в Stalwart.

Настрой домены, пользователей, DNS и TLS. Сертификат NPM обслуживает браузерный HTTPS, но не настраивает автоматически TLS для SMTP и IMAP. Stalwart нужны собственная настройка сертификата и слушатели для соответствующих протоколов.

## Админка через SSH

Способ проверен на Stalwart 1.0.0 после завершения мастера и перезапуска контейнера. Домен, публичный DNS, `/etc/hosts` и `STALWART_PUBLIC_URL` менять не нужно.

1. На своём компьютере открой туннель, если он ещё не открыт через `make tunnel`:

```bash
ssh -N -L 127.0.0.1:20019:127.0.0.1:19019 SSH_HOST
```

2. В другом терминале на своём компьютере один раз зарегистрируй доверенный OAuth-клиент. Замени `admin@example.com` на логин постоянного администратора. `curl` запросит его пароль отдельно; не вписывай пароль в команду:

```bash
curl --fail-with-body --silent --show-error \
  --user 'admin@example.com' \
  --header 'Content-Type: application/json' \
  --data-binary @- \
  http://127.0.0.1:20019/jmap <<'JSON'
{
  "using": ["urn:ietf:params:jmap:core", "urn:stalwart:jmap"],
  "methodCalls": [["x:OAuthClient/set", {
    "create": {
      "tunnelAdmin": {
        "clientId": "http://127.0.0.1:20019/admin/oauth-client.json",
        "description": "Admin via SSH tunnel",
        "firstParty": true,
        "redirectUris": {
          "http://127.0.0.1:20019/admin/oauth/callback": true
        },
        "postLogoutRedirectUris": {
          "http://127.0.0.1:20019/admin/login": true
        },
        "grantTypes": {
          "authorizationCode": true,
          "refreshToken": true
        }
      }
    }
  }, "tunnel-admin"]]
}
JSON
```

Успех: ответ содержит `created.tunnelAdmin.id` внутри `methodResponses`. HTTP `200` сам по себе не подтверждает создание: проверь отсутствие `error` и `notCreated`. Не создавай повторно клиента с тем же `clientId`; для существующего клиента проверь его настройки.

3. Открой `http://127.0.0.1:20019/admin/login`, введи логин постоянного администратора, подтверди доступ для клиента `Admin via SSH tunnel` и войди с паролем. Проверь загрузку списка пользователей и обновление страницы. Для регистрации OAuth-клиента перезапуск контейнера не требуется.

`firstParty` позволяет клиенту работать с правами вошедшего пользователя, но не отменяет вход с паролем. Используй этот параметр только для доверенной собственной админки. При смене локального адреса или порта зарегистрируй соответствующий `clientId` и адреса возврата; `localhost` и `127.0.0.1` не следует взаимозаменять в URL.

HTTP используется на локальном участке; соединение между компьютером и сервером защищено SSH. Не публикуй `8080`/`19019` на `0.0.0.0` и не открывай этот HTTP-адрес наружу. Регистрация клиента **не закрывает административный API через публичный прокси**: ограничения описаны в разделе «Веб-почта и доступ».

Документация: [OAuth clients](https://stalw.art/docs/auth/oauth/clients/).

## Антивирус

Подключи Milter в Stalwart к `stalwart-antivirus:7357`. Включи временный отказ при недоступности фильтра и проверь поведение при ошибке самого сканера. Прежнее имя `antivirus` сохранено как сетевой alias внутри сети `email`.

Наличие контейнера ClamAV само по себе не включает проверку писем. Перед использованием проверь приём SMTP и отправку через SMTP/JMAP, включая письма с вложениями.

## Веб-почта и доступ

Bulwark запускается из официального образа `ghcr.io/bulwarkmail/webmail`. Установка Application внутри Stalwart не нужна. `WEBMAIL_JMAP_URL` должен совпадать с публичным почтовым доменом. Переменная передаётся как `JMAP_SERVER_URL` и пропускает отдельный мастер настройки Bulwark.

В этой конфигурации вход в почту выполняется с логином и паролем обычного почтового пользователя. Отдельная админка Bulwark отключена: `ADMIN_PASSWORD` не задан, `STALWART_ADMIN_ACCESS=off`. Настройки задаются через Compose и `.env`. Телеметрия отключена. Секрет сессий создаётся автоматически в volume, вручную задавать пароль в Compose не нужно.

На форме доступна опция «Запомнить меня». В Bulwark 1.18.0 вход по паролю без этой опции не восстанавливается после перезагрузки страницы. Включай её только на своём устройстве: Bulwark сохраняет зашифрованные данные входа в HttpOnly-cookie. Для публичной веб-почты обязательно используй HTTPS; локальный HTTP-тест требует отдельного, не предназначенного для сервера override `COOKIE_SECURE=false`.

`extra_hosts` направляет `MAIL_HOSTNAME` внутри контейнера на шлюз хоста Docker. Так серверная часть Bulwark обращается к NPM на том же сервере без NAT loopback через внешний IP. Имя домена и проверка TLS сохраняются; `/etc/hosts` компьютера и публичный DNS не меняются. Эта схема предполагает, что NPM публикует `443` на том же Docker-хосте. Если NPM находится на другой машине, адаптируй этот маршрут.

**До публикации нужно настроить изоляцию административного API.** Stalwart использует `/jmap` и для почты, и для управления. Запрет `/admin` закрывает страницу, но не административные операции. Привязка `ADMIN_PORT` к `127.0.0.1` не закрывает доступ через Docker-сеть `proxy`. Текущий Compose сам по себе не обеспечивает администрирование только через туннель.

В Stalwart открой **Management → Accounts → нужный администратор → Credentials → Password → Allowed IPs**. Укажи только точный IP, который Stalwart видит при входе через SSH-туннель. Его можно определить по `remoteIp` успешного входа в логах. Это обычно адрес Docker-шлюза, а не `127.0.0.1`. Не копируй чужой IP и не разрешай всю Docker-сеть. Сначала сохрани открытую рабочую админскую сессию, затем проверь новый вход через туннель.

Ограничь также каждый административный API-ключ и каждый дополнительный пароль. Повтори для всех администраторов. У HTTP оставь **Client IP source = TCP peer address**: доверие произвольным forwarded-заголовкам может изменить результат проверки. Не включай IP NPM или Bulwark в список администратора.

В локальном тесте `allowedIps` у пароля администратора и отдельно у API-ключа запрещает через NPM пароль, ключ и ранее выданный OAuth-токен (`403`). Обычный пользователь читает почту, но административные JMAP-методы получают `forbidden`. Эти ограничения хранятся в Stalwart, не в Compose. После изменения сетей, учётных данных или обработки IP повтори проверки на целевом сервере.

После настройки ограничений создай Proxy Host в NPM:

| Поле | Значение |
|---|---|
| Domain Names | Твой `MAIL_HOSTNAME`, например `mail.example.com` |
| Scheme | `http` |
| Forward Hostname / IP | `bulwark-container` |
| Forward Port | `3000` |

Все изменения NPM выполняй через его панель, не редактируя сгенерированные конфиги. В SSL выбери действующий сертификат домена и включи **Force SSL**. Во вкладке **Settings / Advanced** добавь:

```nginx
client_max_body_size 50m;

location ~* ^/(admin|setup|api/(admin|setup))(/|$) {
    return 404;
}

location ~ ^/(jmap(/|$)|\.well-known/jmap$) {
    set $stalwart_upstream stalwart-container;
    proxy_pass http://$stalwart_upstream:8080;
    proxy_http_version 1.1;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_buffering off;
    proxy_read_timeout 300s;
}
```

Удали прежнее перенаправление `/` на `/webmail/`, если оно было настроено. Главная страница и `/api/` Bulwark идут в контейнер веб-почты. Только JMAP discovery и `/jmap` идут в Stalwart: там же находятся загрузка, скачивание вложений и уведомления. Не перенаправляй весь `/api` в Stalwart. HTTP между контейнерами используется внутри Docker-сети; наружу работает HTTPS NPM.

Блокировка `/admin`, `/setup`, `/api/admin` и `/api/setup` защищает страницы и административные маршруты Bulwark. Защита административных методов Stalwart на общем `/jmap` обеспечивается ограничениями учётных данных выше, а не фильтрацией тела JSON в Nginx. По этой схеме нельзя входить в публичную веб-почту администратором: создай отдельного пользователя с обычной ролью User.

После сохранения проверь вход обычного пользователя, открытие письма, вложения и обновление списка; публичные `/admin/login` и `/api/admin/config` должны возвращать `404`. Через SSH административный JMAP-запрос должен работать, через публичный URL с теми же данными администратора должен получать отказ. Не считай один HTTP `200` успешным JMAP-вызовом: смотри `methodResponses`.

Веб-почта будет доступна на `https://<MAIL_HOSTNAME>/`. Для админки Stalwart используй `http://127.0.0.1:20019/admin/login` через SSH с зарегистрированным OAuth-клиентом из раздела «Админка через SSH». Прямой адрес Bulwark через туннель: `http://127.0.0.1:20020`; сервер JMAP при этом остаётся публичным, поэтому почтовой учётке нужны обычные права.

Документация: [Docker Bulwark](https://bulwarkmail.org/docs/deployment/docker), [настройки](https://bulwarkmail.org/docs/getting-started/configuration), [reverse proxy](https://bulwarkmail.org/docs/deployment/docker/reverse-proxy).

## Команды Makefile

| Команда | Действие |
|---|---|
| `make help` | Показать команды с описаниями |
| `make env` | Создать `.env` из примера без перезаписи |
| `make network` | Создать внешнюю сеть, если она отсутствует |
| `make init` | Скачать образы и поднять контейнеры |
| `make up` | Поднять контейнеры и применить изменения Compose или `.env` |
| `make pull SERVICE=webmail` | Скачать только образ веб-почты |
| `make up SERVICE=webmail` | Запустить или обновить только Bulwark, не перезапуская почтовый сервер |
| `make down` | Остановить и удалить контейнеры, сохранив данные |
| `make restart` | Перезапустить существующие контейнеры |
| `make pull` | Скачать образы указанных версий |
| `make logs` | Логи всех контейнеров (последние 100 строк, live) |
| `make logs SERVICE=stalwart` | Логи почтового сервера |
| `make logs SERVICE=stalwart-antivirus` | Логи антивируса |
| `make logs SERVICE=webmail` | Логи веб-почты |
| `make ps` | Показать состояние контейнеров |
| `make config` | Проверить и показать итоговый Compose-конфиг |

После изменения Compose или `.env` используй `make up`, а не `make restart`. `make config` не проверяет DNS, сертификаты, доставку писем и ограничения доступа.

## Обновление

Сначала сделай резервную копию и проверь инструкции перехода на выбранную версию. Измени `STALWART_VERSION` в `.env`, затем:

```bash
make pull
make up
```
