# Email

Stalwart для почты и ClamAV для проверки писем. Веб-почта Bulwark Lite устанавливается отдельно внутри Stalwart.

## Быстрый старт

Команды выполняются из папки `email`. Сначала создай `.env`:

```bash
make env
```

Отредактируй `.env` и проверь конфигурацию:

```bash
make config
```

Укажи тот же `PROJECT_NAME` и `NETWORK`, что у остальных модулей и Nginx Proxy Manager. В этом окружении это `docker-environment` и `proxy`.

**Не запускай модуль одновременно с Mailu:** оба используют порты `25`, `465`, `993` и `4190`. Сначала подготовь перенос почты и освободи порты, затем:

```bash
make init
```

Команда:
- скачает образы указанных версий,
- создаст внешнюю сеть `NETWORK`, если её ещё нет,
- создаст Docker volumes для данных,
- поднимет контейнеры Stalwart и ClamAV.

`make env` не перезаписывает существующий `.env`. Домены, TLS, DNS, антивирусная проверка и веб-почта настраиваются отдельно. Данные Mailu автоматически не переносятся.

Из корня проекта модуль запускается командой `make email`, а `.env.prod` отправляется командой `make deploy-email`. Общие `make init` и `make deploy` используют `email` вместо прежнего `mail`. Корневой `make init` пропускает модуль, если `email/.env` ещё не создан.

## Настройка `.env`

Перед первым запуском отредактируй `.env`:

| Переменная | Описание |
|---|---|
| `PROJECT_NAME` | Общая группа контейнеров, `docker-environment` |
| `NETWORK` | Внешняя сеть NPM, `proxy` |
| `STALWART_CONFIG_VOLUME` | Имя volume конфигурации, `vennro-email_config` |
| `STALWART_DATA_VOLUME` | Имя volume почты, `vennro-email_data` |
| `CLAMAV_VOLUME` | Имя volume антивирусных баз, `vennro-email_clamav` |
| `MAIL_HOSTNAME` | Почтовое имя сервера, например `mail.vennro.ru` |
| `STALWART_VERSION` | Версия образа Stalwart, сейчас `v1.0.0` |
| `ADMIN_PORT` | HTTPS-порт на `127.0.0.1` для доступа с сервера или через туннель, по умолчанию `19018` |
| `SETUP_PORT` | HTTP-порт первоначальной настройки на `127.0.0.1`, по умолчанию `19019` |

Часовой пояс `Asia/Krasnoyarsk` задан в Compose. `.env` не хранится в Git. Если файл уже существует, добавь в него новые переменные из `.env.example`.

## Порты

| Порт хоста | Назначение |
|---|---|
| `25` | SMTP, приём писем от других серверов |
| `465` | SMTP TLS, отправка писем из приложений и клиентов |
| `993` | IMAP TLS, чтение почты |
| `4190` | ManageSieve, управление пользовательскими фильтрами |
| `127.0.0.1:${ADMIN_PORT}` → `443` | HTTPS Stalwart через локальный порт |
| `127.0.0.1:${SETUP_PORT}` → `8080` | Первоначальная настройка |

Порты ClamAV на хост не публикуются. Stalwart обращается к нему внутри отдельной сети `email`. Только Stalwart подключён к внешней сети `NETWORK`.

## Данные

Хранятся в именованных Docker volumes:

| Volume | Данные |
|---|---|
| `${STALWART_CONFIG_VOLUME}` | Конфигурация Stalwart, `/etc/stalwart` |
| `${STALWART_DATA_VOLUME}` | Данные Stalwart, `/var/lib/stalwart` |
| `${CLAMAV_VOLUME}` | Антивирусные базы, `/var/lib/clamav` |

Папки для данных на хосте вручную создавать не нужно. `make down` сохраняет volumes. Не используй `docker compose down -v`: эта команда удаляет volumes вместе с данными.

Имена volumes заданы явно и по умолчанию сохранены от прежнего проекта `vennro-email`: смена `PROJECT_NAME` не должна создавать пустое хранилище вместо существующей почты. Если модуль уже развёрнут, сначала останови старые контейнеры с прежним Compose-конфигом, сохранив volumes, и только затем запускай обновлённый модуль. Если использовались другие имена volumes, укажи именно их в `.env`.

У модулей общий Compose-проект. Предупреждение об orphan-контейнерах может относиться к соседним модулям: не используй `--remove-orphans` для его устранения.

## Первоначальная настройка

Посмотри пароль первоначальной настройки в логах Stalwart:

```bash
make logs SERVICE=stalwart
```

Не публикуй этот пароль. На Mac открой туннель через настроенный SSH-профиль `vennro`:

```bash
ssh -N -L 20019:127.0.0.1:19019 vennro
```

Открой `http://127.0.0.1:20019` и пройди мастер настройки. Если меняешь `SETUP_PORT`, замени серверный порт `19019` в команде.

Для общего `make tunnel` добавь в корневой `.env` нужные строки без `#` перед значением:

```dotenv
T_EMAIL_ADMIN=20018:127.0.0.1:19018
T_EMAIL_SETUP=20019:127.0.0.1:19019
```

После отключения порта первоначальной настройки убери `T_EMAIL_SETUP`. Туннель только перенаправляет порт: он не настраивает TLS, OAuth и ограничения администратора в Stalwart.

Настрой домены, пользователей, DNS и TLS. Сертификат NPM обслуживает браузерный HTTPS, но не настраивает автоматически TLS для SMTP и IMAP. Stalwart нужны собственная настройка сертификата и слушатели для соответствующих протоколов.

После настройки и проверки HTTPS убери публикацию `SETUP_PORT:8080` из Compose и выполни `make up`.

## Антивирус

Подключи Milter в Stalwart к `stalwart-antivirus:7357`. Включи временный отказ при недоступности фильтра и проверь поведение при ошибке самого сканера. Прежнее имя `antivirus` сохранено как сетевой alias внутри сети `email`.

Наличие контейнера ClamAV само по себе не включает проверку писем. Перед использованием проверь приём SMTP и отправку через SMTP/JMAP, включая письма с вложениями.

## Веб-почта и доступ

Установи Bulwark Lite как Application с префиксом `/webmail`. Для Stalwart 1.0 нужен совместимый пакет с `stalwart-app.json` (Bulwark Lite 1.18.0 или новее).

**До публикации нужно настроить изоляцию административного API.** Stalwart использует `/jmap` и для почты, и для управления. Запрет `/admin` закрывает страницу, но не административные операции. Привязка `ADMIN_PORT` к `127.0.0.1` не закрывает доступ через Docker-сеть `proxy`. Текущий Compose сам по себе не обеспечивает администрирование только через туннель.

В локальном тесте проверен `allowedIps` у пароля администратора и отдельно у каждого его API-ключа: административные запросы через NPM получают `403`, напрямую работают, обычный пользователь отправляет и читает почту. Эти настройки хранятся в Stalwart, не в Compose. IP для туннеля нужно определить на целевом сервере; нельзя просто перенести тестовый IP Docker или разрешить всю общую сеть. Тест выполнялся с `clientIpSource=peer`: изменение обработки forwarded-заголовков требует повторной проверки ограничений.

После настройки ограничений создай Proxy Host в NPM:

| Поле | Значение |
|---|---|
| Domain Names | `mail.vennro.ru` |
| Scheme | `https` |
| Forward Hostname / IP | `stalwart` |
| Forward Port | `443` |

Настрой сертификат публичного домена и перенаправление `/` на `/webmail/`. Проверь сертификат upstream, передачу клиентского IP, вход, вложения и обновление почты.

Веб-почта будет доступна на `https://mail.vennro.ru/webmail/`. Для админки через туннель к `ADMIN_PORT` ещё нужно согласовать HTTPS-адрес, сертификат и OAuth-настройки; произвольный localhost-адрес не гарантирует работу входа.

## Команды Makefile

| Команда | Действие |
|---|---|
| `make help` | Показать команды с описаниями |
| `make env` | Создать `.env` из примера без перезаписи |
| `make network` | Создать внешнюю сеть, если она отсутствует |
| `make init` | Скачать образы и поднять контейнеры |
| `make up` | Поднять контейнеры и применить изменения Compose или `.env` |
| `make down` | Остановить и удалить контейнеры, сохранив данные |
| `make restart` | Перезапустить существующие контейнеры |
| `make pull` | Скачать образы указанных версий |
| `make logs` | Логи всех контейнеров (последние 100 строк, live) |
| `make logs SERVICE=stalwart` | Логи почтового сервера |
| `make logs SERVICE=stalwart-antivirus` | Логи антивируса |
| `make ps` | Показать состояние контейнеров |
| `make config` | Проверить и показать итоговый Compose-конфиг |

После изменения Compose или `.env` используй `make up`, а не `make restart`. `make config` не проверяет DNS, сертификаты, доставку писем и ограничения доступа.

## Обновление

Сначала сделай резервную копию и проверь инструкции перехода на выбранную версию. Измени `STALWART_VERSION` в `.env`, затем:

```bash
make pull
make up
```
