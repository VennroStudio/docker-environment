# LiveKit

Медиа-сервер LiveKit для WebRTC (видео/аудио звонки, real-time коммуникация) в Docker-контейнере.

## Быстрый старт

```bash
make init
```

Команда:
- создаст `.env` из `.env.example` (если его ещё нет),
- создаст внешнюю сеть (если её ещё нет),
- скачает образ и поднимет контейнер.

## Настройка `.env`

Перед первым запуском отредактируй `.env`:

| Переменная            | Описание                                                          |
|-------------------------|---------------------------------------------------------------------|
| `PROJECT_NAME`         | Название проекта (влияет на префикс контейнеров в Docker)          |
| `NETWORK`              | Имя внешней Docker-сети, к которой подключается контейнер          |
| `LIVEKIT_API_KEY`      | API-ключ (используется клиентами и бэкендом для аутентификации)    |
| `LIVEKIT_API_SECRET`   | Секрет к API-ключу — генерируй случайной строкой (`openssl rand -hex 32`) |

## Настройка `livekit.yaml`

Файл не содержит секретов и безопасен для хранения в git — API-ключ/секрет приходят из `.env` через переменную `LIVEKIT_KEYS`, которая имеет приоритет над файлом. В `livekit.yaml` — только структурные настройки (порты RTC, диапазон UDP-портов, режим определения внешнего IP).

## ⚠️ Порты — здесь есть исключение из общего правила

В отличие от остальных сервисов, часть портов LiveKit **пробрасывается напрямую на хост** — через reverse-proxy типа nginx proxy manager их не провести, потому что это не HTTP-трафик, а «сырые» протоколы WebRTC-сигнализации и медиа:

- **`7880` (сигнализация/WebSocket)** — HTTP-протокол, идёт как обычно через внешнюю сеть и NPM (домен → `livekit-container:7880`). Не забудь включить тумблер **«Поддержка WebSocket»** в настройках прокси-хоста.
- **`7881/tcp`** — TCP-фолбэк для медиа-потока, пробрасывается напрямую (`ports:` в compose)
- **`50000-60000/udp`** — диапазон UDP-портов для медиа (аудио/видео) каждого участника звонка, тоже пробрасывается напрямую

Убедись, что на файрволе/у хостинг-провайдера открыты `7881/tcp` и весь диапазон `50000-60000/udp`, иначе участники не смогут установить медиа-соединение (сигнализация будет работать, а звук/видео — нет).

**`use_external_ip: true`** в `livekit.yaml` включает автоопределение публичного IP сервера — обычно этого достаточно для одиночного сервера с прямым публичным IP. Если сервер находится за NAT/балансировщиком (например, у некоторых облачных провайдеров) — потребуется явно задать `node_ip` в `livekit.yaml`.

## Команды Makefile

Полный список — `make help`.

| Команда | Действие |
|---|---|
| `make init` | Первичная инициализация: `.env` + сеть + pull + up |
| `make up` | Поднять контейнер |
| `make down` | Остановить и удалить контейнер |
| `make restart` | Перезапустить контейнер |
| `make logs` | Логи контейнера (последние 100 строк, live) |
